# ML System Design Document: Harry Potter RAG

## 1. Зачем идем в разработку продукта?

Цель проекта - создать интерактивную систему, позволяющую пользователям задавать вопросы о сюжете, персонажах, местах и других деталях из книг Гарри Поттера и получать точные ответы, сгенерированные LLM с опорой на исходный текст книг. Это решает проблему трудоемкого поиска информации в длинных текстах и предоставляет удобный способ получения знаний из вселенной Гарри Поттера.

## 2. Бизнес-требования и ограничения

*   **Функциональные требования:**
    *   Система должна принимать текстовый вопрос пользователя.
    *   Система должна находить релевантные фрагменты текста из книг Гарри Поттера (поиск).
    *   Система должна генерировать ответ на основе найденных фрагментов и вопроса (генерация).
    *   Система должна отображать ответ пользователю (через API или веб-интерфейс в будущем).
*   **Нефункциональные требования:**
    *   Ответы должны быть точными и соответствовать содержанию книг.
    *   Время отклика системы (на начальном этапе) может быть умеренным (например, до 30 секунд).
    *   Система должна быть прототипом или минимально жизнеспособным продуктом (MVP).
*   **Ограничения:**
    *   Использование только текста книг Гарри Поттера как источника знаний (пока без фильмов, вики и т.д.).
    *   Возможные ограничения API LLM (если используется внешний, например, OpenAI).
    *   Ограничения по вычислительным ресурсам на этапе разработки/тестирования.

## 3. Что входит в скоуп проекта/итерации, что не входит

*   **Входит:**
    *   Подготовка текста книг (очистка, разбиение на чанки).
    *   Выбор и настройка векторного хранилища (например, Chroma, FAISS).
    *   Выбор и интеграция LLM (например, OpenAI GPT, или open-source вариант).
    *   Реализация RAG-пайплайна (поиск + генерация).
    *   Разработка простого API (например, с FastAPI).
*   **Не входит:**
    *   Создание сложного веб-интерфейса (может быть в следующих итерациях).
    *   Поддержка аудио/видео из фильмов.
    *   Интеграция с внешними API, кроме LLM и возможно векторного хранилища.
    *   Поддержка других серий книг.

## 4. Предпосылки решения

Использование RAG позволяет LLM опираться на конкретный источник знаний, снижая вероятность "hallucinations" и обеспечивая актуальность ответов на основе книг. Тексты книг Гарри Поттера доступны (при условии соблюдения авторских прав для исследовательских целей в рамках курса). Существуют мощные LLM, доступные через API или локально, подходящие для генерации ответов.

## 5. Постановка задачи

Реализовать систему, которая принимает вопрос пользователя (например, "Как создать Философский камень?") и возвращает ответ, сформированный на основе информации, найденной в текстах книг Гарри Поттера, с использованием LLM. Основная метрика успеха - релевантность и точность сгенерированных ответов (на данном этапе планируется оценка вручную или с помощью простых метрик в будущем).

## 6. Блок-схема решения

[Вопрос пользователя]
        ↓
[Поиск релевантных фрагментов из книг (Retriever)]
        ↑
[Векторное хранилище ← Предобработка и векторизация текстов книг]
        ↓
[Формирование промпта: "Контекст + Вопрос"]
        ↓
[LLM генерирует ответ]
        ↓
[Ответ пользователю]
